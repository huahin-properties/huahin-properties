รอบนี้ยัง "ไม่แก้พฤติกรรมอะไรเลย"
ไม่แก้กฎการบันทึกข้อมูล ไม่แก้การจัดประเภทของ AI
ไม่แตะ C4.2a ไม่เริ่ม Step 2

รอบนี้ทำอย่างเดียวคือ: ทำให้เรา "มองเห็น" ว่าแต่ละครั้งที่ลูกค้าคุย
ระบบตัดสินใจอะไร และบันทึกหรือไม่บันทึก เพราะอะไร

เหตุผล: วันที่ 7 ก.ย. เวลา 10:28 และ 10:36 ระบบถูกเรียกจริง
ได้ผล 200 (สำเร็จ) ทั้งสองครั้ง แต่ไม่มีเอกสารสนทนาใหม่ใน Firestore
และ log เดิมไม่แสดงว่า AI ตัดสินระดับ (stage) ว่าอะไร
จึงยังสรุปสาเหตุไม่ได้ — รอบนี้เพิ่มการบันทึกให้เห็น


--------------------------------------------------------
ไฟล์ที่ต้องอัปโหลด (2 ไฟล์)
--------------------------------------------------------

1) functions/index.js          → ต้อง deploy (ดูข้อ B)
2) ContactRail.dc.html         → อัปโหลดเฉย ๆ ขึ้นเองอัตโนมัติ

ไฟล์อื่นไม่ต้องแตะ
(conversation-firestore.js, firestore.rules, firebase-client.js ไม่เปลี่ยน)


--------------------------------------------------------
A. อัปโหลดขึ้น GitHub (หน้าจอสีขาว = เว็บ GitHub)
--------------------------------------------------------

1. เปิดหน้า repo ใน GitHub
2. กด  Add file → Upload files
3. ลากไฟล์  ContactRail.dc.html  ลงไป
4. เข้าไปในโฟลเดอร์ functions ก่อน แล้วกด Add file → Upload files
   แล้วลากไฟล์  index.js  ลงไป
5. กด Commit changes


--------------------------------------------------------
B. Deploy ฟังก์ชัน (หน้าจอสีดำ = Codespace terminal)
--------------------------------------------------------

1. ใน GitHub กดปุ่มเขียว Code → Codespaces → สร้าง/เปิด Codespace
2. รอจนเห็นช่องสีดำด้านล่าง (terminal)
3. พิมพ์ทีละคำสั่ง รอให้เสร็จก่อนพิมพ์คำสั่งถัดไป:

       npm install -g firebase-tools

       firebase login --no-localhost

   (จะได้ลิงก์ → เปิด → อนุญาต → คัดลอกรหัสกลับมาวาง)

4. คำสั่ง deploy รอบนี้ (ฟังก์ชันเดียวเท่านั้น):

       firebase deploy --only functions:receptionTurn

5. รอจนขึ้น  ✔  Deploy complete!

หมายเหตุ: รอบนี้ deploy แค่ receptionTurn
ไม่ต้อง deploy createCaseFromConversation (ไม่ได้แก้)


--------------------------------------------------------
C. วิธีทดสอบ — ข้อความเดียวจบ (POSITIVE CONTROL)
--------------------------------------------------------

จุดสำคัญ: ต้องเป็นข้อความที่ "ต้องบันทึก" ชัดเจน
ไม่ใช่คำถามทั่วไป เพราะคำถามทั่วไปแยกไม่ออกว่าระบบทำงานหรือเปล่า

1. เปิด Chrome หน้าต่างใหม่แบบ Incognito
2. เปิดเว็บ huahin.properties
3. กด F12 (เปิดช่อง Console ด้านข้าง) — สำคัญ
4. กดปุ่มแชท 💬 แล้วพิมพ์ข้อความนี้ ข้อความเดียว:

   ผมมีบ้านที่หัวหิน อยากขายประมาณ 8 ล้านบาท ช่วยประเมินราคาให้หน่อยครับ

5. รอ AI ตอบ

6. ดูใน Console จะเห็นบรรทัดหน้าตาแบบนี้:

   [reception-diag] receptionTurn rid=a1b2c3d4e5f6 persisted=true stage=advisory

   → จด rid เอาไว้ (ตัวอักษร-ตัวเลขชุดนั้น)

   ความหมาย:
   • route=receptionTurn + persisted=true  → ทำงานถูกต้อง บันทึกแล้ว
   • route=receptionTurn + persisted=false → เซิร์ฟเวอร์ทำงาน แต่ AI ตัดสิน
     ว่ายังเป็นคำถามทั่วไป (ปัญหาอยู่ที่การจัดประเภท ไม่ใช่เส้นทาง)
   • route=legacy_fallback... หรือ backend_init_failed...
     → เรียกเซิร์ฟเวอร์ไม่สำเร็จ ใช้ทางสำรองเดิมตอบลูกค้า (ปัญหาอยู่ที่เส้นทาง)

7. เปิด Firebase Console → Firestore → conversations
   ต้องเห็นเอกสารใหม่ชื่อ  reception__xxxx

8. เปิด Firebase Console → Functions → receptionTurn → Logs
   ค้นด้วย rid ที่จดไว้ จะเห็นบรรทัด:
      turn_start  → รับคำขอ
      classified  → AI ตัดสิน stage / primaryIntent อะไร
      turn_done   → persisted true/false และ reason


--------------------------------------------------------
D. สิ่งที่ log ไม่เก็บ (ความเป็นส่วนตัว)
--------------------------------------------------------

ไม่เก็บ: ข้อความลูกค้า, ข้อความ AI, ชื่อ, เบอร์โทร, อีเมล, LINE,
requirementsSummary, ค่าใน propertyBasics, trackToken, uid เต็ม

เก็บเฉพาะ: การตัดสินใจ (stage / primaryIntent / persisted / เหตุผล /
สร้างใหม่หรือใช้เอกสารเดิม / รหัส error), ความยาวข้อความเป็นตัวเลข,
และ uid 4 ตัวท้าย (ตัวเดียวกับที่แสดงเป็น "ผู้เยี่ยมชม xxxx" อยู่แล้ว)


--------------------------------------------------------
E. หลังทดสอบเสร็จ ส่งข้อมูลนี้กลับมา
--------------------------------------------------------

1. บรรทัด [reception-diag] จาก Console (คัดลอกทั้งบรรทัด)
2. บรรทัด classified และ turn_done จาก Functions Logs
3. มีเอกสาร reception__ ใหม่หรือไม่

แล้วจะสรุปสาเหตุจริงได้ และแก้จุดเดียวถูกจุดในรอบถัดไป
