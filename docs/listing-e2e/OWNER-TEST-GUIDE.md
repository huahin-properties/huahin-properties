## 1) สิ่งที่เจ้าของต้องทำ (น้อยที่สุด)
**หน้าขาว = Firebase Console → โปรเจกต์ `huahin-chat-test-01`** (เช็กชื่อโปรเจกต์มุมซ้ายบนทุกครั้ง ต้องไม่ใช่ `huahin-properties-5f1b5`)
1. Authentication → Sign-in method → เปิด **Email/Password** และ **Anonymous**
2. Firestore Database → ต้องมีฐานข้อมูลแล้ว (ถ้ายังไม่มี: Create database, ตำแหน่ง asia-southeast1)
3. Storage → ต้องกด **Get started** แล้ว (มี bucket) — ถ้ายังไม่เคย ให้กดตอนนี้ (สคริปต์ deploy Storage ไม่ได้ถ้ายังไม่มี)
4. Project settings → Your apps → ต้องมี **Web app อย่างน้อย 1 ตัว** (ถ้าไม่มี: Add app → Web)
5. แผนแบบ Blaze (Functions ต้องใช้) — ถ้าตั้งวงเงิน 25 บาทไว้ บริการอาจหยุดเมื่อเต็ม ซึ่งเป็นผลของวงเงินที่ตั้งใจ

**หน้าดำ = Codespace** (เปิดบนกิ่ง `claude/listing-e2e-01`)
6. พิมพ์ `bash tools/listing-test/deploy-test.sh` → ถ้าถูกขอให้ login ทำตามที่หน้าดำบอก (วางโค้ดกลับที่หน้าดำ) → ดูแผนที่แสดง (ต้องเห็น `huahin-chat-test-01 (NOT production)`) → พิมพ์ `DEPLOY-TEST` → รอจนขึ้น `DONE. Test site: https://huahin-chat-test-01.web.app`
   สคริปต์ deploy เฉพาะ: ฟังก์ชัน 10 ตัวตามชื่อ **จากโฟลเดอร์แยก `build/listing-functions` ที่ไม่มี secret (ตัวเลือก `functions:listing:<ชื่อ>` — ต้องมีชื่อ codebase)** (ถ้า deploy จาก `functions/` ตรงๆ Firebase CLI จะตรวจ secret ทุกตัวของระบบ — AI/Stripe/อีเมล/LINE — ใน Secret Manager ก่อนกรอง `--only` แล้ว 403 เมื่อโปรเจกต์ไม่มี; พิสูจน์ด้วยเทสต์ F1), Firestore rules, Storage rules, หน้าเว็บ — **ไม่มีขั้นขอคีย์ AI** ส่งภาพหน้าดำให้ Work/Code ดูได้ (ไม่มีความลับในนั้น)

**หน้าขาว = Firebase Console อีกครั้ง (สร้างบัญชีทดสอบ 2 คน)**
7. Authentication → Users → Add user: `owner` (อีเมลอะไรก็ได้ที่เจ้าของจำได้, รหัสผ่านตั้งเอง) และ `staff` — คัดลอก **User UID** ของแต่ละคน
8. Firestore → เริ่มคอลเลกชัน `adminUsers` → เอกสาร ID = UID ของ owner: `role` = `owner`, `email`, `displayName` (ทั้งหมดเป็น string) → เอกสาร ID = UID ของ staff: `role` = `staff`, `email`, `displayName`
เสร็จ — ไม่มีขั้นอื่น (ไม่ต้อง allow-list, ไม่ต้องใส่คีย์)

## 2b) อัปเดตเว็บ TEST ที่ deploy ไปแล้ว (รักษาเคสและรูปเดิม — เจ้าของไม่ต้องส่งใหม่)
เหตุ: Staff เห็นช่องรูปสีเทาบน TEST จริง — หน้าเว็บขอรูปส่วนตัวจาก Storage ตรงๆ พร้อม header `Authorization` ซึ่งเบราว์เซอร์ **บล็อกด้วย CORS** (`No 'Access-Control-Allow-Origin'`) เพราะ bucket ยังไม่มีนโยบาย CORS. แก้โดยให้หน้าขอรูปผ่านฟังก์ชัน `getCasePhoto` (เฉพาะ Owner/Staff, เฉพาะรูปส่วนตัวที่บันทึกไว้ของเคสนั้น, ไม่มี token, ไม่เปิดเป็นสาธารณะ) → **ไม่ต้องตั้งค่า bucket CORS เลย**
หน้าดำ Codespace: `git pull origin claude/listing-e2e-01` แล้ว `bash tools/listing-test/deploy-test.sh huahin-chat-test-01` → พิมพ์ `DEPLOY-TEST` (รันซ้ำได้: ฟังก์ชัน 10 ตัวถูกเขียนทับ, rules เดิม, หน้าเว็บถูกแทนที่; **ข้อมูลใน Firestore และไฟล์ใน Storage ไม่ถูกแตะ** เคส/รูปเดิมยังอยู่)
จากนั้นหน้าเบราว์เซอร์: เปิด `/Listing%20Approvals.dc.html` ด้วย Staff แล้วกด **Ctrl+Shift+R** (ล้างแคช) → รูปควรขึ้น; ถ้ายังเทา: F12 → Network → ดูรายการ `getCasePhoto` (สถานะ 200 = ผ่าน, 403 = บัญชีนี้ไม่มีเอกสาร `adminUsers`, 404 `photo_not_recorded` = เคสไม่มีรูปที่บันทึกไว้) แล้วส่งภาพมา
หมายเหตุ: รายการ `GET /%7B%7B lightboxSrc %7D%7D → 404` ในแท็บ Network เป็นเสียงรบกวนเดิมของตัวรันหน้า (ขอรูปจากเทมเพลตก่อน bind) ไม่ใช่สาเหตุของช่องเทา

## 2c) แก้: เห็นรูปแรกรูปเดียว อีก 6 ช่องเทา (หัวข้อ 2b แก้ไปแล้วรอบก่อน)

(ไม่ใช่ CORS/สิทธิ์: คำขอเดียวที่ส่งไปตอบ 200)
แก้: โหลดรูปที่เหลือของเคสทีละ 4 รูปทันทีที่หน้าโหลด, คลิกรูปจะโหลดส่วนที่ขาดก่อนเปิด, ลิสต์รูปใหญ่เรียงตรงกับแถบ (รูปที่โหลดไม่ได้เป็นกรอบว่างแดง ไม่ทำให้รูปอื่นเลื่อน). สิทธิ์เดิมไม่เปลี่ยน (ผ่าน `getCasePhoto` เท่านั้น ไม่มี token ไม่เปิดสาธารณะ). **อัปเดต TEST: โค้ดฟังก์ชันไม่เปลี่ยน มีแต่หน้าเว็บ** — ใช้คำสั่งเดิม `bash tools/listing-test/deploy-test.sh huahin-chat-test-01` (ฟังก์ชันถูกเขียนทับด้วยโค้ดเดิม ไม่เป็นไร) แล้ว Ctrl+Shift+R

## 4) แชท AI จริง — แยกต่างหาก (ไม่ต้องทำเพื่อทดลองฟอร์ม)
สถานะ: **ยังไม่มีผลทดสอบ AI จริงเลย** (เทสต์ทั้งหมดใช้ AI จำลอง) และ **ห้ามกลับไปรันสคริปต์ CHAT-LIVE ที่ค้างขั้น 6/8** ถ้าจะทำ ให้ทำหลังข้อ 2 ผ่านและ Work อนุญาตเท่านั้น สิ่งที่ต้องมี:
1. **คีย์ Anthropic ใหม่ที่ใช้เฉพาะ TEST** + วงเงินที่เจ้าของตั้งเอง — เจ้าของเป็นคนเก็บ (ผมไม่ขอ ไม่เห็น ไม่รับในแชท)
2. **ข้อควรระวัง:** ฟังก์ชันแชทอยู่ใน `functions/index.js` ที่ประกาศ secret ทั้งระบบ — การ deploy 5 ตัวนี้ด้วย `--only` จะเจอปัญหา Secret Manager แบบเดียวกัน (ต้องมีทั้ง Secret Manager API และขั้นตอนแยกโฟลเดอร์สำหรับแชทด้วย — **ยังไม่ได้ทำ/ทดสอบ** เป็นงานแยกก่อนเริ่มข้อนี้)
   หน้าดำ Codespace (ทีละคำสั่ง ตอบกลับผลก่อนไปต่อ): 
   `npx --yes firebase-tools@15.32.1 functions:secrets:set ANTHROPIC_API_KEY --project huahin-chat-test-01` (วางคีย์ที่ช่องซ่อนในหน้าดำนั้น)
   `npx --yes firebase-tools@15.32.1 deploy --only functions:receptionTurn,functions:getPropertyDraft,functions:updatePropertyDraft,functions:createCaseFromConversation,functions:claudeComplete --project huahin-chat-test-01`
3. **Allow-list + เพดาน** (ไม่มี = ปฏิเสธ ไม่ใช่ไม่จำกัด): เปิดเว็บ → คัดลอก UID จากแถบเหลือง → Firestore เพิ่ม `chatTestAllow/<UID>` = `{ enabled: true }` และ `chatTestConfig/limits` = `{ globalCap: <เช่น 50>, perUidCap: <เช่น 10> }` (ตัวเลข)
4. smoke test แรก: UID ที่ไม่อยู่ใน allow-list ต้องถูกปฏิเสธ (401/403) ก่อน แล้วค่อยลอง UID ที่อยู่ใน list
**Blockers/ไม่ทราบ:** (ก) ยังไม่ได้ยืนยันว่า gate อ่านโหมดโปรเจกต์ถูกต้องบน Cloud จริง (smoke test ข้อ 4 คือตัวยืนยัน) (ข) เจ้าของต้องมีคีย์ใหม่พร้อม (ค) เครือข่ายของ Code ยังบล็อกโดเมนเว็บจริง Code จึงเปิดหน้า TEST ที่ deploy แล้วเองไม่ได้ — การลองจริงทำโดยเจ้าของ (ถ้าจะให้ Code ช่วยดู ต้องเพิ่มโดเมนใน Network access ตาม `docs/testing/CHAT-LIVE-01-DEPLOY.md` §4)
