# SEC-URGENT-01 — ค่าเริ่มต้นบัญชีแอดมินในไฟล์สาธารณะ (งานความปลอดภัยเร่งด่วน แยกจาก CHAT-LIVE-01)

สถานะ: **บันทึกเพื่อให้ Work/เจ้าของจัดลำดับ — ยังไม่แก้ ยังไม่ทดสอบการล็อกอินใด ๆ บน production**
ผู้พบ: Code ระหว่างทำ CHAT-LIVE-01 (1 ต.ค. 2569) · ฐานที่ตรวจ `8c549c6`

## ห้ามนำค่ามาแสดงซ้ำ
เอกสารนี้ **ไม่ระบุค่าใด ๆ** (ชื่อผู้ใช้ รหัสผ่าน อีเมล เบอร์) — ผู้ตรวจดูที่ไฟล์/ชื่อตัวแปรเอง ชุดทดสอบและสคริปต์ build ของ CHAT-LIVE-01 ไม่คัดลอกค่าเหล่านี้ไปไว้ที่ใด และไม่มีการลองล็อกอิน production

## พบอะไร (ตำแหน่งและชื่อ ไม่ใช่ค่า)
| ไฟล์ | สิ่งที่พบ |
|---|---|
| `firebase-client.js` — ค่าคงที่ `DEFAULT_ADMIN_CREDENTIALS` | มีชื่อผู้ใช้และรหัสผ่านแอดมินแบบข้อความล้วน พร้อมอีเมลและเบอร์สำหรับกู้คืนจริง ถูกส่งไปกับไฟล์ที่ทุกเบราว์เซอร์ดาวน์โหลดได้ (ไฟล์เดียวกับที่หน้าเว็บสาธารณะ import) |
| `firebase-client.js` — `DEFAULT_FB_FOOTER` | เบอร์โทร อีเมล และลิงก์กลุ่มจริง (ข้อมูลติดต่อ ไม่ใช่รหัสผ่าน) |
| `index.html` — ฟังก์ชัน `submitGate` | ฝังอีเมลแอดมินจริงสำหรับล็อกอินประตูปรับปรุงเว็บ |

## ความเสี่ยง (ตามที่อ่านจากโค้ด ยังไม่ได้ยืนยันว่าใช้เข้าระบบจริงได้)
- ค่าที่เคย **เผยแพร่ในไฟล์สาธารณะแล้ว** ต้องถือว่ารั่ว: **การลบออกจากโค้ดอย่างเดียวไม่ทำให้รหัสที่เผยแพร่ไปแล้วใช้ไม่ได้** (ไฟล์เก่าอยู่ใน git history, แคชเบราว์เซอร์, สำเนาของบุคคลอื่น)
- ที่ยังไม่ทราบ (ต้องให้เจ้าของ/Work ตรวจในฝั่งที่มีสิทธิ์ ไม่ใช่ Code): ค่าเริ่มต้นนี้ยังตรงกับบัญชีแอดมินที่ใช้งานจริง หรือเอกสาร `settings/admin` ใน Firestore ถูกเปลี่ยนไปแล้วหรือไม่ และบัญชี Firebase Auth ของแอดมินใช้รหัสเดียวกันหรือไม่

## ขอบเขตที่เสนอ (แพ็กเกจแยก ต้องให้ Work อนุมัติ)
1. **เจ้าของเปลี่ยน/เพิกถอนข้อมูลยืนยันตัวตนจริงก่อน** (เปลี่ยนรหัสผ่านบัญชีแอดมินใน Firebase Authentication และเอกสารตั้งค่าแอดมิน, ตรวจ/ยกเลิกเซสชันเก่า, ตรวจ Authentication/Firestore logs ว่ามีการเข้าใช้ที่ไม่คุ้นเคยหรือไม่) — ผมจะเขียนขั้นตอนทีละหน้าจอให้เมื่อ Work สั่ง
2. จากนั้น Code ลบค่าเริ่มต้นออกจากโค้ดสาธารณะ (ให้ล้มแบบปิดเมื่อไม่มีเอกสารแอดมิน แทนการถอยไปใช้ค่าในโค้ด) พร้อมชุดทดสอบด้วยข้อมูลสังเคราะห์/emulator เท่านั้น
3. ตรวจ git history และพิจารณาว่าต้องล้างประวัติหรือไม่ (ตัดสินโดยเจ้าของ — ล้างประวัติไม่ทำให้ค่าที่รั่วแล้วปลอดภัย การเปลี่ยนค่าต่างหากที่สำคัญ)

## สิ่งที่ CHAT-LIVE-01 ทำเกี่ยวกับเรื่องนี้ (และไม่ทำ)
- test build แทนค่าเหล่านี้ด้วยค่าสังเคราะห์ที่ใช้ไม่ได้ และปฏิเสธการ build ถ้ายังเหลือ `password:` ที่ไม่ใช่ค่าสังเคราะห์ — เพื่อไม่ให้ระบบทดสอบพกค่าจริงไปด้วย
- **ไม่แก้ไฟล์ production, ไม่ล็อกอิน production, ไม่ยืนยันว่าค่าเหล่านั้นยังใช้ได้**
